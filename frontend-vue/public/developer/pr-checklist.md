# 模块接入 PR 检查清单

> 所有硬门禁通过后才能进入测试环境。测试通过不代表获得生产发布授权。

## 1. 范围与设计

- [ ] 已说明是扩展现有模块，还是新增独立业务应用。
- [ ] 已提交并校验 `module-manifest`，示例或规划能力未写成已上线。
- [ ] 新 `appCode`、工作台来源或流程分支已取得明确评审结论。
- [ ] 改动范围没有混入无关重构或其他人的未完成文件。

## 2. 前端接入

- [ ] 页面、API 封装和 TypeScript 类型已补齐。
- [ ] 路由已配置 `meta.appCode` 或 `anyAppCodes`。
- [ ] 菜单、直接 URL 和非菜单入口使用一致的应用准入。
- [ ] 按钮权限只改善交互，未被当作后端安全边界。
- [ ] `npm.cmd run typecheck` 通过。
- [ ] `npm.cmd run check:access` 通过。
- [ ] `npm.cmd run build` 通过。

## 3. 后端与数据边界

- [ ] API 前缀已登记应用准入，操作权限已明确。
- [ ] Service 层校验当前用户对具体记录、部门、供应商或任务的对象范围。
- [ ] 详情、修改、审批、删除、导出使用一致的数据范围。
- [ ] 不信任前端传入的用户、部门、供应商或权限范围标识。
- [ ] 参数校验和错误响应不会泄露内部异常、SQL 或敏感配置。

## 4. 流程

- [ ] 采购、审批、报价、飞书或 AI 改动复用了现有服务、节点、状态和审计记录。
- [ ] 没有直接 SQL 改状态、影子状态、旁路表或绕过服务的外部回调。
- [ ] 确需新增流程分支时，已附业务负责人确认和普通/异常路径说明。

## 5. 数据库

- [ ] `schema.sql` 未用于共享或需要保留数据的数据库。
- [ ] 新增脚本位于 `backend-springboot/sql/zz_*.sql`，未修改已执行的历史脚本。
- [ ] 脚本可重复执行，结构变更和数据修复均限定作用范围。
- [ ] 数据修复说明了预计影响、实际影响和恢复依据。
- [ ] 未把 `manual_*.sql`、备份或回滚脚本接入常规自动迁移。

## 6. API 与文档

- [ ] 新接口说明了方法、路径、鉴权、请求、响应、错误码和对象权限。
- [ ] 已检查当前 `/v3/api-docs` 变化。
- [ ] 未把 `docs/backend-api-routes.csv` 当作实时接口合同。
- [ ] 行为、权限、路由、SQL 或部署变化已同步更新相关文档。
- [ ] 文档没有账号、密码、令牌、生产数据或真实网络标识。

## 7. 构建与安全硬门禁

后端：

```powershell
cd backend-springboot
mvn.cmd -q -DskipTests compile
mvn.cmd test
```

前端：

```powershell
cd frontend-vue
npm.cmd ci
npm.cmd run typecheck
npm.cmd run check:access
npm.cmd run build
```

仓库：

```powershell
git diff --check
```

- [ ] 改动相关单元或集成测试通过。
- [ ] 依赖变化已完成对应安全审计。
- [ ] 密钥与敏感信息扫描通过。
- [ ] PR 构建检查通过。

任一硬门禁失败或缺失时，不进入测试发布。

## 8. 测试环境验收

- [ ] 首页、登录和 `/api/auth/me` 正常。
- [ ] 测试环境 `/v3/api-docs` 可读取且包含预期变化。
- [ ] 变更页面/API主路径通过。
- [ ] 有权限、无权限、无应用准入和对象越界场景均已验证。
- [ ] 数据迁移重复执行不会失败或重复污染数据。
- [ ] 外部通知仅使用测试目标，不触达正式对象。
- [ ] 验收记录包含测试提交、结果和已知限制。

## 9. 生产红线

- [ ] 本 PR 没有把“测试成功、合并或文档完成”描述成生产授权。
- [ ] 未访问或修改生产主机、数据库、凭据、通知目标和发布工作流。
- [ ] 若后续申请生产发布，将另行走明确授权和生产发布流程。
