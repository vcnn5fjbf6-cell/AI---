# 采购原因审核基础规则

## 理由充分性

- “使用”“备用”“办公使用”“工作需要”“业务需要”“领导要求”等词语本身不能证明采购必要性。
- 有效采购原因应尽量说明具体使用场景、当前问题、采购目的、必要性或预期效果。
- 多条明细可以分别描述原因；审核时应逐条读取，不能用其中一条代替其它明细。
- 不要求申请人补充采购原因之外的字段。

## 审查边界

- 不读取申请标题、采购类型、部门、金额、紧急程度、需求日期、商品名称、规格、数量、单价或商品链接。
- 不根据未提供的信息推测商品适配性、数量合理性、价格合理性或紧急性。
- 采购原因中主动提到紧急事件时，可以判断其文字是否说明了业务影响，但不得引用系统中的紧急程度字段。
- 确定性字段校验、金额计算和审批路由由采购系统负责，不属于 AI 审核意见范围。

## 风险结论

- 采购原因缺失或表达含糊时优先使用 `SUPPLEMENT`，不要直接使用 `RETURN`。
- 采购原因明确表示个人消费、与业务无关或规避正常流程时，可以使用 `RETURN`。
- 没有正式制度依据时，只能指出风险和需人工核实的事项，不能声称违反某项具体制度。

## 示例

- “办公使用” → `SUPPLEMENT`，需补充具体使用场景、当前问题和采购必要性。
- “现有值班终端频繁死机，采购用于恢复机房监控值守” → 可 `APPROVE`。
- “设备漏水影响机房运行，采购维修配件用于恢复排水” → 可 `APPROVE`。
- “购买高端手机作为个人备用机” → `RETURN`，采购原因明确显示非业务用途。
