# AI 知识库与 Skill 治理

## 目标

平台管理员可以在“平台管理 / AI知识与技能”中维护模型运行所需的业务知识和执行指令，不需要为了调整规则重新发布应用。模型在业务运行中发现规则缺口时，只能提交待审核建议，不能直接修改生效内容。

## 内容模型

- **知识库**：保存可被多个 Skill 复用的制度、判断规则和业务知识。编码创建后不可修改。
- **Skill**：保存模型执行步骤，并通过稳定编码引用一个或多个知识库。编码创建后不可修改。
- **修订历史**：新增、人工修改、模型建议通过和删除都会保留完整快照、修订号、操作人和时间。
- **改进建议**：模型提交完整替换正文和改进理由，初始状态只能是 `PENDING`。

当前内置内容为：

- Skill：`procurement-compliance-review`
- 知识库：`procurement-compliance-rules`，保存采购原因优化、填写框架和预审共用的唯一标准
- Skill：`procurement-purpose-optimization`，引用同一知识库，只优化并返回采购原因草稿，不保存、不提交、不执行审批

## 生效流程

```text
业务调用模型
  -> 读取当前启用 Skill
  -> 组合其引用的启用知识库
  -> 输出业务建议
  -> 可选：提交完整的内容改进建议
  -> 建议进入待审核列表
  -> 系统管理员对比当前正文与建议正文
      -> 拒绝：当前内容不变
      -> 通过：目标正文更新、修订号 +1、记录审核人与完整快照
```

模型不得执行审批动作、改数据库业务状态或直接激活自己的建议。管理员通过建议和内容更新在同一事务中完成；失败时两者都不生效。

## 采购合规审查接入

`PurchaseRequestService.submit` 完成已有字段、数量、价格和金额校验后，统一调用采购合规审查 Skill。页面提交、批量导入后提交、飞书 AI 候选转正式申请以及退回重提都走同一个正式提交入口，并覆盖写入 `purchase_request.ai_review_opinion`。

- Dify 候选阶段意见仍是草稿参考，不是正式审批结论。
- MiniMax 只判断采购原因是否说明使用场景、现状及影响和采购必要性。只有原因主动表明批量、覆盖、替换、备用比例或紧急情形时，才检查相应的数量、影响或时限依据；不得因未提供其它申请字段要求补充。
- 每条预审意见同时返回统一缺项编码，页面据此只回填该行缺少的字段；旧接口没有缺项编码时才回退为三项核心框架。
- 低置信度、模型不可用或知识内容异常时，返回人工复核提示，不阻断原审批流程。
- 模型建议必须指向当前上下文中已存在的 Skill 或知识库编码，未知目标会被忽略。
- 相同目标修订和相同建议正文通过 SHA-256 去重，避免重复进入审核队列。

## 采购原因优化接入

采购明细编辑弹窗的“AI优化”调用 `/api/workflow/purchase-requests/purpose-optimize`。后端每次请求都读取数据库中启用的 `procurement-purpose-optimization` Skill，仅当数据库读取异常时才使用随包 Skill；Skill 被停用时接口明确不可用，不绕过治理配置。

- 模型只接收当前明细的采购原因，不接收申请标题、部门、商品、数量、价格或审批信息。
- 优化内容只允许整理原文已有事实，不得虚构库存、地点、人员、数量、故障、时限或制度依据。
- 优化和预审共同引用 `procurement-compliance-rules`；核心项为使用场景、现状及影响和采购必要性，条件项只在原文主动触发时检查。
- 原文信息不足时返回与预审一致的 `【请补充】` 框架，不得用“满足实际使用需求”“保障相关工作正常开展”等泛化套话代替事实。
- 返回内容只追加到当前浏览器草稿；接口不保存明细、不提交申请、不改变预审或审批状态。
- 模型不可用、返回空内容或 Skill 停用时保持原文不变，并向申请人提示重试或联系管理员。

## 管理权限

管理接口统一位于 `/api/admin/ai-governance/**`，要求：

1. 当前账号具有平台应用权限和 `platform_ai_governance:manage` 权限；
2. 后端再次确认当前账号属于系统管理员角色；
3. 前端隐藏或显示按钮不能替代后端权限校验。

## 接口概览

- `GET /api/admin/ai-governance/overview`：知识库、Skill 和最近改进建议总览。
- `POST/PUT/DELETE /api/admin/ai-governance/knowledge-bases`：知识库增删改。
- `POST/PUT/DELETE /api/admin/ai-governance/skills`：Skill 增删改。
- `GET /api/admin/ai-governance/revisions`：按目标查询完整修订历史。
- `POST /api/admin/ai-governance/proposals/{id}/review`：管理员通过或拒绝模型建议。

启用的知识库仍被启用 Skill 引用时禁止删除。建议先解除引用或停用对应 Skill。

## 测试要求

发布前至少验证：

1. 知识库和 Skill 可以新增、编辑、停用、删除，并生成修订记录。
2. 启用 Skill 能组合其引用的启用知识库；停用内容不会进入模型提示词。
3. 模型建议只生成 `PENDING` 记录，当前正文不变。
4. 拒绝建议不改变正文；通过建议更新正文、修订号和审核记录。
5. 非系统管理员调用管理接口返回无权限。
6. 采购申请正式提交仍走原审批流程，模型异常不会阻断提交。
7. 采购原因优化每次读取启用 Skill，并与预审 Skill 引用同一采购原因标准；结果只更新浏览器草稿，停用 Skill 或模型异常时原文不变。
8. 普通理由不会被要求补充未提供的数量或紧急字段；原文主动触发批量或紧急条件时，优化、填写框架和预审使用相同的条件项。

## 恢复

修订历史保存每个版本的完整 JSON 快照。当前页面先提供查看与复制，不提供一键回滚；如需恢复，管理员应将目标修订正文复制到编辑框、填写恢复说明并保存，从而生成一条新的可审计修订，不能覆盖或删除历史记录。
