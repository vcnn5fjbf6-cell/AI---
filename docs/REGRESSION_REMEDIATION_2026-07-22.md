# 全量回归缺陷整改记录（2026-07-22）

## 范围与结论

本轮按要求不改动 EHS 板块和 AI 知识库/治理内容，不执行安全审查，不接触生产环境。已完成代码修复和本地发布前门禁；当前仍是测试环境候选版本，尚未合并到 Gitee `main`，也尚未部署到 151。

| 模块 | 问题 | 整改结果 |
| --- | --- | --- |
| 订单发票 | 供应商无法在订单内上传、被退回后重传，采购人/来源部门助理/当前楼长缺少查看、下载、确认和退回闭环 | 新增版本化发票提交、附件鉴权下载和审核闭环；供应商上传入口不再与查看入口重复 |
| 售后 | 关键字在分页后过滤，记录数与总数不一致；重复申请被期限提示覆盖 | 过滤下沉到数据库分页前，并优先返回已有售后状态提示 |
| 个人劳保 | 可在采购、供应商确认或收货完成前提前确认领用 | 仅原申领人可操作，且必须完成需求审批、中标确认和对应订单明细收货；重复确认幂等 |
| 流程测试 | 测试按钮直接写报价或确认表，未覆盖正式业务校验和副作用 | 仅 `test` Profile 可用；归集、供应商报价和中标确认均调用正式领域服务，并在模拟供应商后恢复原登录身份 |
| 审批记录 | 流程重新打开时 `ended_at` 因 ORM 忽略 `null` 而残留 | 增加显式清空 SQL，覆盖重新提交、常规流转、人工替换确认和替换确认超时路径 |
| 用户删除 | 删除用户后平台准入记录残留 | 在同一事务内删除角色绑定和 `platform_user_app_access` |
| 人员批量导入 | 部门编码或名称无法唯一解析时仍可能写入不完整部门信息 | 编码、名称必须同时解析成功；歧义行返回中文错误并保留行号 |
| 采购明细导入 | 后端预览缺少模板和值校验，且小数数量可预览成功、提交失败 | 后端校验表头、必填项、采购类型、正整数数量、正数单价和日期格式 |
| 参数异常 | 缺少请求参数被当作通用错误 | 统一返回 `VALIDATION_ERROR` 和中文缺参提示 |
| 错误台账 | `/api/procurement/**` 被归到错误模块 | 归类为 `PROCUREMENT` |
| 前端路由 | 直接访问 `/assets` 被 Nginx 当作静态目录处理 | 增加精确路由并回退 SPA 首页 |
| 菜单 | 尚未验收的维保静态原型出现在正式菜单 | 从菜单隐藏，保留原路由用于后续单独验收 |
| 前端构建 | 大型图表和组件依赖混入公共业务包 | 将 ECharts/ZRender 和 Element Plus 拆分为独立构建块；大型依赖仍会产生体积提示，但不再与业务代码混包 |
| Gitee 测试部署 | 旧测试镜像持续累积，清理失败可能造成部署状态不一致 | 每端保留当前运行版本和最近版本、合计最多 3 个；只清理本项目 Gitee 标签镜像，禁止全局 prune；清理失败告警并在收尾后原子推进状态 |

## 验证结果

- 后端：排除 EHS 与 AI governance 测试包后，30 个测试类、120 个用例全部通过，失败 0、错误 0。
- 前端：`vue-tsc --noEmit` 与 Vite 生产构建通过；应用准入、采购申请部门、用户区域 3 项源码门禁通过。
- 上线管理服务：43 个 Node 测试全部通过。
- 部署脚本：`bash -n` 通过；镜像列表失败、镜像元数据失败、空镜像列表和不同保留数量的 mock 场景通过。
- 差异检查：`git diff --check` 通过。
- 开发 Skill：更新项目避坑清单后通过 `quick_validate.py`。

## 尚未关闭的发布门禁

1. 订单发票仍需在 151 使用供应商、采购人、来源部门助理和当前楼长四种真实账号完成 multipart 上传、下载、退回、重传和确认联调，并验证 Flyway V32 在真实 MySQL 上执行。
2. 生产发布前必须确认数据库备份与 `data/order-invoices` 附件目录属于同一恢复点，并执行文件大小和摘要一致性恢复演练；当前仓库文档已记录，尚不能据此判定生产就绪。
3. 测试环境审批基础数据是否与生产一致属于受控数据同步任务，不在本次代码提交中处理，也没有读取或改动生产数据。
4. “替换商品确认后的第二次履约/收货”仍缺少明确产品规则，本轮没有擅自新增状态或旁路流程。
5. 候选分支需推送并通过面向最新 `main` 的 PR 构建后，才可合并到 Gitee `main` 触发 151 部署。
