4. 采购核心流程板块

说明普通采购、紧急采购、AI 创建采购申请、月度汇总、供应商报价和中标确认如何走同一条主流程。

核心流程 
flowchart TB
    A["采购需求来源"]
    A --> A1["人工新建采购申请"]
    A --> A2["飞书 AI 助手生成候选"]
    A --> A3["批量导入 Excel"]
    A --> A4["个人劳保申领"]

    A1 --> B["PurchaseRequestService 创建申请"]
    A2 --> B
    A3 --> B
    A4 --> B

    B --> C{"普通采购 / 紧急采购"}
    C -->|普通采购| D["楼长/经理等普通审批节点"]
    C -->|紧急采购| E["紧急采购审批节点"]

    D --> F["审批通过"]
    E --> F
    F --> G["进入月度需求池 / 汇总"]
    G --> H["供应商报价"]
    H --> I["报价审核 / 比价"]
    I --> J["确认中标"]
    J --> K["供应商确认"]
    K --> L["生成订单 / 收货 / 发票 / 售后"]

    D --> R["整单退回或单项驳回"]
    E --> R
    R --> B
  • AI 助手只是输入采集层，不能绕过 PurchaseRequestService 和原审批流程。
  • 普通采购和紧急采购仍走原有流程节点，不能新建旁路。
  • 单项驳回是“驳回部分明细，其他明细继续流转”，不能只停留在卡片状态。

8. 权限与外部系统开放 API（规划板块）

说明后续如果给外部系统调用人员权限，建议放在独立开放 API 层，避免直接暴露后台管理接口。

规划 
flowchart TB
    EXT["外部系统"]
    EXT --> GW["Nginx / API 网关"]
    GW --> AUTH["OpenAPI 鉴权拦截器"]
    AUTH --> A1["app_key"]
    AUTH --> A2["HMAC 签名"]
    AUTH --> A3["IP 白名单"]
    AUTH --> A4["接口范围 scope"]

    AUTH --> API["/openapi/v1/permission/check"]
    API --> USER["系统用户服务"]
    API --> ROLE["角色权限服务"]
    API --> LOG["OpenAPI 调用审计日志"]

    USER --> DB["MySQL"]
    ROLE --> DB
    LOG --> DB
  • 外部系统只建议查“某人是否有某权限”，不要直接开放改角色、删用户、改权限。
  • 每个外部系统一个 app_key/app_secret，并记录调用日志。
  • 返回数据要最小化，不返回飞书 open_id、手机号、密码、token 等敏感字段。
